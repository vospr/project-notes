# Course 4 · Chapter 4.2: The F3 benchmark and patch classification

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** The rebuild's data and task: the public F3 North Sea facies benchmark, 32x32 patches labelled at the centre pixel. Test accuracy 0.717 but macro-F1 0.514; classes 4 and 5 are almost never found (recall 0.09 and 0.02).

## 2. The problem (business view, plain English)

After the v1 failure (chapter 4.1) the project needed real labels, so that "beats a baseline" could mean something. The public **F3 facies benchmark** (Alaudah et al. 2019) is a seismic volume from the Dutch North Sea with a facies label for every sample point, made by interpreters. Facies are rock units with a characteristic seismic look. The task here is deliberately small: given a 32×32 window of the seismic image, say which facies sits at its centre. It is a stand-in classifier on a real, public problem; the pipeline around it is the product.

Finance analogy: you are classifying firms into six rating buckets, and 52% of firms are in one bucket. A model that says "bucket 2" for everyone is 52% accurate and useless. You judge it by how well it finds the small buckets, because that is where the risk is.

## 4. How it works (data to prediction)

```

        |

 X (n,32,32) float32, y (n,) int64  ->  flatten to (n,1024)  ->  Pipeline(scaler, PCA 32, HGB)
```
(Array shapes: *local headers*; the repo itself only implies 401 sections, *tests/test_06:18*.)

**Sampling**: `make_patches` draws `n` random (section, row, column) triples with a seeded generator, copies the 32×32 window, and takes the label of the centre pixel `labels[i, r + size//2, c + size//2]`. Sampling is **with replacement and unstratified**: class shares in the sample follow the area of each facies. `test_01_data.py:40-48` checks that the label is the centre pixel and that windows stay in bounds, on a toy volume.

**Sets**: train = 20,000 patches from one block of the train volume, validation = 5,000 from a separate block (chapter 4.4), test1 = 5,000 from the benchmark's separate volume. A 600/300/300 version of the same sampling is committed as the CI fixture (*data.py:99-107*, chapter 4.6).

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| Public F3 facies benchmark | Keep random labels; unsupervised anomaly detection | Real labels, real task, citable, checksummed download | Labels are interpreters' picks, not measured truth (general property; not in the repo docs) |
| Patch classification, centre-pixel label | Full per-pixel segmentation with a U-Net | Small, fits scikit-learn and a laptop; keeps the pipeline the focus | Throws away spatial context beyond 32×32; boundary patches are mixed |
| 6 classes as in the benchmark | Merge rare classes | Honest task definition | Two classes the model cannot find |
| Random positions inside a block | Dense tiling; stratified by class | Simple, seeded, reproducible | Overlapping patches, no class balance, with-replacement duplicates |
| Raw amplitudes flattened (1024 values) | Handcrafted texture features, CNN | Pipeline = scaler + PCA + GB on raw pixels (chapter 4.3) | A CNN is the natural model; review suggests a small 2D CNN |
| Accuracy and macro-F1 both reported | Accuracy only | Imbalance makes accuracy flattering | Macro-F1 has its own pitfalls |
| No class weighting | `class_weight`, oversampling | "No hyperparameter search" by design | Rare classes ignored |

## 6. Theory behind it (the "lecture" part)

### 6.1 Seismic facies, in one paragraph
Reflection seismology sends sound into the ground and records echoes, giving a 3D volume of amplitudes indexed by (inline, crossline, time or depth). A **seismic facies** is a group of reflections with similar shape, continuity and strength, which an interpreter links to a rock type or depositional setting. Interpreters mark facies by hand on sections. Machine learning tries to learn the mapping from the image around a point to the interpreter's label. Because rock layers are laterally continuous, **neighbouring points have nearly the same image and label**. This spatial correlation drives everything in chapter 4.4.

*In my project:* the benchmark gives a 3D image and a same-shaped 3D label volume; I reduce it to single-label patches.

### 6.2 Patch classification versus segmentation
- **Segmentation:** predict a label for every pixel (U-Net, fully convolutional networks). Output has the shape of the input.
- **Patch (window) classification:** cut a window around a point, predict one label for the window (the centre). Dense output needs a sliding window. Cheap to train, wasteful at inference, loses long-range context.

The window size trades context against locality: larger windows see more structure but mix several facies near boundaries.

*In my project:* 32×32 windows, one label each, no sliding-window inference, no segmentation map.

### 6.3 The confusion matrix and the metrics built on it
For class c: precision P_c = TP/(TP+FP), recall R_c = TP/(TP+FN), F1_c = 2·P_c·R_c/(P_c+R_c) (harmonic mean). Aggregations over K classes:
- **Accuracy** = Σ π_c R_c, recall weighted by class share π_c.
- **Macro-F1** = (1/K) Σ F1_c; every class counts the same.
- **Weighted-F1** = Σ π_c F1_c.
- **Balanced accuracy** = (1/K) Σ R_c.
- **Micro-F1** over all decisions equals accuracy for single-label problems.

The **accuracy paradox**: with one dominant class, accuracy can be high while the model ignores the rest. Choose the metric that matches the cost: if each class matters equally, use macro averages; if the business cares about the large class, accuracy is fine.

Macro-F1 pitfalls: (a) a class with no true samples and no predictions is *not* in the average (scikit-learn averages over labels present in either y_true or y_pred), so the average changes with the sample; (b) rare classes with tens of samples make F1 jump by large steps (one more correct prediction of 45 moves recall by 2.2 points).

*In my project:* accuracy 0.717 versus balanced accuracy 0.545 versus macro-F1 0.

### 6.4 Baselines
A baseline answers "compared to what?". A good set, from weakest to strongest: (1) majority class, (2) prior-matched random guess, (3) a simple model on the same input (logistic regression, k-NN), (4) the incumbent model. A result is only informative relative to the strongest baseline you can cheaply build. Chance levels: accuracy max π_c; prior-matched guess Σ π_c²; its macro-F1 is 1/K (derivation in chapter 4.1).

*In my project:* the gate uses baseline (1) and the incumbent (4). Baseline (3) exists only as a model-choice study: logistic regression got 0.507 validation accuracy against a 0.531 majority baseline, so the PCA features are not linearly useful. Baseline (2), K = 6 for test1, would give macro-F1 ≈ 0.167, against the model's 0.514.

### 6.5 Class imbalance and distribution shift
Three standard remedies: **reweight the loss** (`class_weight`), **resample** (over- or under-sample), or **adjust the decision rule** after training. If only the class priors differ between training and deployment (label or prior shift) and P(x|y) is unchanged, the Bayes-optimal posterior is corrected by Bayes' rule: p_new(y|x) ∝ p_train(y|x) · π_new(y)/π_train(y). A class that is 3% of training and 15.6% of deployment should be upweighted about 5×. Using test priors for that correction is itself test leakage unless priors come from outside the test labels.

*In my project:* class 4 is 3.0% of training patches and 15.6% of test1, and its recall is 0.09 with precision 0.78. That pattern (rarely predicted, right when predicted) is what a model that believes class 4 is rare would do. But a *covariate* difference between regions (the facies looks different there) could produce the same pattern; the logs cannot tell the two apart.

### 6.6 Sampling and effective sample size
Random patches inside one block are not independent: overlapping windows share pixels and neighbours share labels. For m correlated observations with average intra-cluster correlation ρ, the effective sample size is about n/(1 + (m−1)ρ) (Kish's design effect). With ρ near 1, 5,000 patches may carry the information of a few hundred independent ones.

*In my project:* the ±0.6-point standard error for accuracy (√(0.717·0.283/5000)) assumes independence and is therefore too small; the README itself notes "patches within a block overlap spatially" and "no confidence intervals".

## 8. Glossary

| Term | One-line definition |
|---|---|
| Seismic facies | A group of seismic reflections with similar character, linked to a rock type |
| Volume / section | The 3D amplitude array / one 2D slice of it (`volume[i]`) |
| Patch | A 32×32 window cut from a section |
| Centre-pixel label | The patch's label is the facies at its middle pixel |
| F3 | A North Sea survey block; the benchmark's source |
| test1 / test2 | The benchmark's two held-out volumes (`test_once/` folder) |
| Macro-F1 | Unweighted mean of per-class F1 |
| Balanced accuracy | Unweighted mean of per-class recall |
| Accuracy paradox | High accuracy from predicting the dominant class |
| Prior (label) shift | Class shares differ between training and deployment |
| Covariate shift | The input distribution P(x) differs between training and deployment |
| Design effect | Factor by which correlation shrinks the effective sample size |
| Majority-class baseline | Always predict the most frequent training class |
