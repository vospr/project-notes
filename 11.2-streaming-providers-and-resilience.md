# Course 11 · Chapter 11.2: Streaming providers and resilience

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** How the harness turns provider calls into typed streaming events and survives failure: SSE decoding, providers never throw, four failure layers (transport retry, stall watchdogs, rate-limit rotation and fallback, context overflow), never replay shown output, model roles and key rotation.

## 2. The problem (business view, plain English)

An agent run is a chain of dozens of model calls, each a long-lived streaming HTTP request to a service you do not control. Over a long unattended run almost everything that can go wrong does: the Wi-Fi flips, the gateway returns a one-off 500, the provider throttles you, the endpoint goes silent without closing the connection, the model returns an empty answer, a vendor invents a new `finish_reason`, the context no longer fits. If any one of these ends the run, the user loses work, and an unattended job (a benchmark, a CI agent) simply fails.

The harness needs one place that turns all of these into a small, uniform vocabulary the loop can deal with, and a policy for which ones to retry, which to fail over, which to surface. That is this layer.

Finance analogy: this is the market-data and order-gateway layer. Feeds drop, venues reject, a counterparty goes quiet. The trading logic upstairs should see "order filled", "order rejected: reason X", "venue down, rerouted to venue Y", never a raw socket exception.

## 4. How it works (technical walkthrough)

### 4.1 One model call, as events
The loop calls a **`StreamFunction`**: `(model, context, cancelToken) → AssistantMessageEventStream` (*AL* typedef near line 108, call near line 1478). That stream emits a fixed sequence of sealed event types (*TY* lines 682-861):

```
StartEvent
  TextStart → TextDelta* → TextEnd
  ThinkingStart → ThinkingDelta* → ThinkingEnd
  ToolCallStart → ToolCallDelta* → ToolCallEnd     (one per tool call)
DoneEvent(message)         ← normal end
ErrorEvent(error message)  ← any failure; message.stopReason = error | aborted
```

Every delta carries the **partial message so far** (partial-first). The class `AssistantMessageEventStream` completes on `DoneEvent` or `ErrorEvent`, and `await stream.result` gives the final `AssistantMessage`; for an error, that is the error message itself (*ES* lines 105-125). So the caller never needs a `try/catch` for network problems.

The stop reason says what happened: `stop`, `length` (hit the token limit), `toolUse`, `error`, `aborted` (*TY* line 19). Note `length`: the loop refuses to execute tool calls from a message that stopped because of the token limit, because their arguments may be cut off (*AL* around line 1330, "A `length` stop means the output was cut off ...").

### 4.2 Turning bytes into events
- **SSE decoder**: a hand-written decoder for Server-Sent Events, ported from pi's Anthropic adapter. It takes a stream of text chunks that can be split anywhere, finds line breaks, and yields `ServerSentEvent{event, data, raw}`; multiple `data:` lines are joined with `\n` as the spec says. Bytes are decoded to text upstream (`utf8.decoder`).
- **Shared adapter plumbing**: request-header merging, HTTP error carriers, the "send and race against abort" helper, SSE wiring, block-end dispatch and the terminal error event. It exists so the three provider ports stay close to pi and the duplication gate (under 1%) passes (*PC* lines 1-10).
- **One OpenAI-compatible adapter** is reused by swapping `baseUrl` for OpenRouter, DeepSeek, Kimi, Grok and others; there are separate adapters for Anthropic, Google, ChatGPT (Codex OAuth), Copilot (device flow), DIAL, MiniMax, z.ai, CodeMie, Ollama, and custom providers saved from the REPL (*README* "Providers"; folder listing).

### 4.3 The four layers of failure handling
| Layer | File | Catches | What it does |
|---|---|---|---|
| 1. Transport retry | `providers/transient_retry_stream.dart` | socket-level failures: reset, refused, unreachable, timed out, broken pipe, TLS handshake cut; gateway 5xx | waits (fixed delay, 5 s default in the header; later changes added a ladder with `Retry-After` and dual budgets), then replays the call |
| 2. Stall watchdogs | `providers/stall_sentinel.dart`, `provider_tuning.dart` | silence: no connect within the connect budget, no chunk within the idle budget | aborts the request with a timeout error; first dumps the outbound payload for post-mortem |
| 3. Rate-limit rotation and fallback | `model_roles/fallback_stream.dart`, `key_rotation.dart` | 429 and quota wording; also transient transport errors (in-place retry with the same backoff) | rotate to the next API key; if all are benched, fall to the next model in the role's chain; mid-turn take-over, visible notice |
| 4. Context overflow | `overflow.dart` + compaction | "prompt is too long" wordings from about 20 providers | **not retried here**; flagged `isContextOverflow` and handed to compaction (chapter 11.4) |

The boundaries are deliberate and documented. Layer 1 says rate limits "stay with the roles layer", auth failures stand, overflow "belongs to compaction", and the idle watchdog's timeout wording is deliberately *not* matched (the endpoint went silent; a replay re-arms the watchdog anyway) (*TRS* lines 5-12). Layer 3 says overflow is excluded "same boundary as omp" (*FB* lines 17-20).

### 4.4 The "observable output" guard
All the retry layers share one rule from oh-my-pi: **if the stream already showed the user content, do not silently replay it from scratch.** Replaying would duplicate text or tool calls that the host already rendered or executed. So a post-output failure stands, with two refinements:
- a **connection-class** failure after *completed* blocks resumes from that prefix (issue #1168), and
- since issue #1323 the first **thinking** delta also counts as committed, because reasoning streams live to the screen; a failure mid-reasoning resumes from the prefix instead of replaying (*TRS* lines 14-28).
An opt-in flag `transientRetryBufferThinking` keeps the older trade-off: buffer thinking silently, so a failure can still be replayed cleanly, at the price of no live reasoning display.

### 4.5 Stall forensics
When a watchdog fires on a silent request, the sentinel first writes the **outbound payload** to a dump directory (`payload.bin`, plus `meta.json` with method, URL, redacted headers, the watchdog name, the idle budget and the payload's SHA-256), then lets the abort land. `scripts/replay_hang.sh` re-sends the dumped payload against the live endpoint: exit code 2 means the stall reproduced, 0 means the endpoint answered. Header redaction is an **allowlist** (only known-safe header names survive; everything else is masked as `REDACTED:<name>`), because a blocklist always lags new credential header names (*SS* lines 18-40). The pure-Dart file decides what to dump; the disk writer sits in `stall_sentinel_io.dart`, reachable only through `lib/io.dart` — the ports-and-adapters rule applied to forensics.

### 4.6 Other loop-side guards around the call (*AL* lines 1377-1535)
- **Degenerate-empty retry.** A completion that stops normally with no tool calls and no non-blank text is retried, bounded by `maxEmptyRetries`. The empty message stays in the transcript, as a truthful record.
- **Tool-call pairing repair** before every request (chapter 11.3).
- **Over-window guard.** If the estimated request is bigger than the model window, the loop does not send it. It offers the host one synchronous emergency compaction; if that fails, the run ends with a clear error carrying the marker `Context window exhausted`, and the post-run auto-compaction shrinks the transcript for the next turn (*AL* lines 1536-1560; issue #387).
- **Self-healing pairing retry.** If the provider answers with a tool-pairing 400, the loop re-runs the repair and retries once (issue #85).

### 4.7 Model roles, key rotation and the provider queue
- **Roles**: `default`, `smol` (cheap, used for compaction summaries), `slow` (careful), `plan`. Each role is an ordered **chain** of `provider/modelId` entries. An unset role inherits the `default` chain. Path-scoped overrides apply by glob (*RC* lines 1-25).
- **Key rotation** (`ApiKeyRing`): stacked keys `NAME`, `NAME_2`, `NAME_3`; round-robin across sessions, **session affinity** (one run keeps one key until it is rate-limited), per-key backoff (*KR* lines 6-19).
- **Fallback engine**: walks the chain; the produced message always carries the identity of the model that actually answered, and a `FallbackNotice` callback lets the host print a `[roles]` line, so degradation is never silent (*FB* lines 23-30).
- **Provider queue** (issue #418): an ordered list of provider entries replacing main-model resolution; it advances on seven "death kinds" (quota, auth, network, timeout, malformed, 5xx, finish_reason) and never advances on content filter or user abort. A literal `apiKey` in config is a hard parse error: keys are referenced by environment variable name only (*PQ* headers).
- **Capability resolver** (gh-1426): ONE precedence for context window, max output tokens and thinking level: user override per provider+model, then role slot, then endpoint-published, then shared catalog, then a global clamp. Thinking pinned on a model that has no reasoning is dropped with a loud note, never silently sent (*CAP* lines 1-30).
- **`finish_reason` classes** (issue #312): transient (heal on replay), terminal (policy and refusal words; retrying a filter would be a safety bug) and unknown (default to transient, but loud-logged so the table grows) (*TY* lines 45-130).

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives considered | Why this one | Cost / risk |
|---|---|---|---|
| Providers return events, never throw | Throw typed exceptions | One failure shape for the loop | Each adapter must catch everything; defensive code still sits in the loop |
| Retry **inside one provider call** (a wrapper on `StreamFunction`) | Retry at the session layer after `agent_end`, as omp does | The loop stays untouched; compaction summaries and plugins get the same policy (*FB* lines 8-13) | Retry state is hidden inside the stream function, harder to see in traces |
| Classify errors by message regex | Typed error codes from each adapter | Vendors return free text and inconsistent codes; one pattern list covers 20 providers (*OVF* lines 1-45) | Brittle against wording changes; false matches possible; needs an exclusion list for rate-limit text |
| Never replay after visible output | Always replay | Avoids duplicated tool calls and text (*TRS* lines 14-28) | A late failure ends a long answer; resume logic adds complexity |
| Resume from the committed prefix (#1168, #1323) | Fail the turn | Mid-stream disconnects stop costing whole turns | The anchor logic must be exact or it duplicates output |
| Overflow is for compaction, not retry | Retry with a shorter context | Overflow is deterministic: a retry of the same request fails again | Needs a second subsystem and a cut-point policy |
| Allowlist for forensic headers | Blocklist of known secret headers | Unknown future credential headers stay masked (*SS* lines 31-40) | Useful headers can be missing from dumps |
| Sticky key per session | Rotate on every request | Predictable quota use per run; spread across sessions | One key can run hot before rotation kicks in |
| Per-provider watchdog tuning, data-driven (#1398) | Fixed global timeouts | A slow reasoning model needs a longer idle budget than a fast one; recipe: idle ≈ 2× measured p95 inter-chunk gap | Needs measurement before tuning |

## 6. Theory behind it (the "lecture" part)

### 6.1 Server-Sent Events (SSE)
SSE is a W3C standard for one-way streaming over HTTP. The server keeps the connection open and sends text lines: `event: name`, `data: ...`, a blank line ends an event; multiple `data:` lines concatenate with newlines; lines starting with `:` are comments (used as keep-alives). The client must handle chunks that split a line or a UTF-8 character anywhere, which is why a decoder works on a text stream after UTF-8 decoding and keeps a line buffer. Browsers have `EventSource`; LLM clients write their own because they need POST bodies, custom headers and finer error handling.

*In my project (11):* the hand-rolled decoder is ported from pi's Anthropic adapter and reused by all providers.

### 6.2 Streaming and partial results
A stream gives the user first tokens in a fraction of the full latency. The consumer sees **deltas**, small increments. A **partial-first** API also hands over the accumulated message so far, so a UI never has to keep its own assembly state. Tool-call arguments arrive as JSON fragments that are not valid JSON until the end, so a field like `partialArguments` holds the unparsed text until the call is complete (*TY* header, third bullet).

*In my project:* the TUI and the Flutter app render from the same partial message.

### 6.3 Retries, backoff, idempotency
A retry is safe only if repeating the request cannot cause harm twice. An LLM call is *read-like* (the same prompt can be sent again), but a stream that already showed output or executed a tool is not. Standard tools: **exponential backoff** (delay doubles up to a cap), **jitter** (random spread so many clients do not retry in lockstep), honouring the server's **Retry-After**, and a **retry budget** (a hard cap so retries cannot amplify an outage). Good practice is to separate budgets by failure class, as here (connection class 4, stream class 3, independent counters).

*In my project:* `Retry-After` wins over the ladder for that attempt, capped at 60 s; `0` counts as absent; an HTTP-date value falls back to the ladder. I did not see jitter in what I read.

### 6.4 Timeouts and watchdogs
Two different silences matter: *connect* (no response headers) and *idle* (the stream opened, then no bytes for too long). A plain overall timeout cannot tell a slow reasoning model from a dead connection. A watchdog resets on every chunk. Tuning by measurement (p50/p95 of the gap between chunks) beats guessing.

*In my project:* the recipe `streamIdleTimeoutMs ≈ 2 × p95` and a report that prints per-model gaps (*CL*, issue #1398).

### 6.5 Failover, circuit breakers and the thundering herd
A **fallback chain** moves load to another provider when one fails. A **circuit breaker** stops calling a failing dependency for a cool-down period instead of hammering it. Here the per-key and per-entry backoff (`keyBackoff` one minute) plays that role. Key rotation spreads load; session affinity keeps behaviour predictable.

*In my project:* the notice on fallback is the audit trail — "no silent degradation".

### 6.6 Error classification: codes versus text
A robust client classifies on structured fields (HTTP status, error `type`, `code`). LLM providers are inconsistent: some return only a message, gateways in front of providers rewrite bodies, and local servers (llama.cpp, LM Studio) use their own wording. A pragmatic client therefore matches known strings and keeps the table growing from production logs, and keeps an *unknown* class with a safe default. This repo does that for overflow, rate limits, transport errors and `finish_reason`.

*In my project:* the `FinishReasonClass.unknown` default is "transient, but log loudly" — the fix for issue #312, where terminal-by-default killed turns on new vendor words.

### 6.7 Context windows and token accounting
Every model has a context window (input plus output). Providers report usage per response; a harness needs it inline to price calls and to decide when to compact. Overflow is not an HTTP "error you can retry"; it needs a smaller prompt.

*In my project:* see Course 2.3 (my cost per call) and chapter 11.4 (this repo's compaction).

## 8. Glossary

| Term | One-line definition |
|---|---|
| `StreamFunction` | The function type `(model, context) → event stream` that every provider implements |
| `AssistantMessageEvent` | Sealed family: start, text/thinking/tool-call start-delta-end, done, error |
| Partial-first | Each delta event carries the message assembled so far |
| `StopReason` | Why a message ended: stop, length, toolUse, error, aborted |
| SSE | Server-Sent Events: one-way text streaming over HTTP |
| Watchdog | A timer reset by activity; fires on silence (connect or idle) |
| Stall sentinel | Dumps the outbound payload when a watchdog fires, for replay |
| Observable-output guard | Never silently replay a stream that already showed content |
| Role | Intent slot (`default`, `smol`, `slow`, `plan`) mapped to a model chain |
| Fallback chain | Ordered list of models tried when one fails |
| Key ring | Several API keys for one provider, rotated with backoff and affinity |
| `finish_reason` class | transient / terminal / unknown retryability of a vendor stop word |
| Context overflow | Input larger than the model's window; handled by compaction, not retry |
| `Retry-After` | Server hint for how long to wait before retrying |
| Death kind | Reason a queue entry is skipped: quota, auth, network, timeout, malformed, 5xx, finish_reason |
