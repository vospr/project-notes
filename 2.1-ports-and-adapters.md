# Course 2 · Chapter 2.1: Ports and adapters (hexagonal architecture)

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** How the governed AI workflow is structured: ports (Protocols and frozen DTOs), Mem0 and Letta adapters, a composition root and contract tests run against each adapter. Key rule: the LLM port returns tokens, never dollars.

## 2. The problem (business view, plain English)

Verdaca is sold on one idea: the governance record must survive a change of vendor. If the memory store, the model provider or the compression tool is replaced, the record of "who asked, what evidence, what it cost" must keep the same shape. That is only true if no vendor type leaks into the core.

Finance analogy: a general ledger with a chart of accounts. Banks, brokers and payment providers change, but each one posts to the ledger through a fixed journal-entry format. The ledger never imports a bank's file format. Ports are the journal-entry format; adapters are the bank connectors; the contract test is the reconciliation that every connector must pass.

## 4. How it works (technical walkthrough)

```
          ┌────────────── composition/ (wiring only) ──────────────┐
          │  builds adapters, hands them to kernel as ports        │
          └───────┬──────────────────────────────────┬─────────────┘
                  ▼                                   ▼
   kernel/ (gateway, auth, mac ...)          adapters/ (mem0, letta, litellm, ...)
   depends on ports only                     each implements one port
                  │                                   │
                  └────────────►  ports/  ◄───────────┘
                         Protocols + frozen DTOs, no vendor imports
```

**Ports.** A port is a `typing.Protocol` plus DTOs. Example: `MemoryPort` has five methods: `store`, `query`, `promote`, `revoke_promotion`, `migrate` (`ports/.../memory.py:185-227`). It is `@runtime_checkable`, so `isinstance(adapter, MemoryPort)` works structurally. Every DTO inherits `VerdacaDTOMixin`, which sets `frozen=True, extra="forbid"` and requires `schema_version` and `correlation_id` (`common.py:110-122`). `extra="forbid"` is the guard: if Mem0 returns a field Verdaca did not ask for, construction fails, so the adapter must pick what to expose. The ports package says it has "no upstream imports" (`memory.py` docstring).

**Errors.** Five base errors (`VerdacaPortError`, `TransientError`, `ContractViolation`, `UpstreamUnavailable` ...) in `common.py:30-100`; adapters raise subclasses. `TransientError` = retry; `UpstreamUnavailable` = degrade.

**Adapters.** `Mem0Adapter` (`adapters/mem0/.../adapter.py:210`) and `LettaAdapter` (`adapters/letta/.../adapter.py:332`) each implement `MemoryPort`. `on_init` self-checks `isinstance(self, MemoryPort)` and raises if not (`mem0/adapter.py:277-278`).

**One rule worth remembering: the LLM port returns tokens, never dollars.** `LLMResponse` has `input_tokens`, `output_tokens`, `finish_reason` and no cost field (`llm_proxy.py:85-107`). Three layers strip cost: DTO `extra="forbid"`; a `CostFieldLeakage` error at the port; a prefix strip in the LiteLLM adapter (`adapter.py:30-48`). Cost is computed only by the cost meter (see 2.3).

**Composition.** `build_gateway(...)` takes eleven keyword-only dependencies, all ports or auth objects, with no defaults (`kernel/gateway/.../composition.py:25-59`). A test pins that signature (`test_ast_gates_stage13.py` `test_gate_c`). Concrete adapters are chosen in `composition/src/praxis/composition/runtime_gateway.py` (imports at lines 112-145; lazy imports of LiteLLM, PiMono, Letta at 344, 413, 448).

**Contract tests.** One suite per port, run against each adapter. Memory: `@pytest.fixture(params=["mem0", "letta"])` builds each adapter over a fake client and the same 14 tests run on both (`test_memory_contract.py:495-503`); two more tests take both adapters in one function to assert parity (set-equality, cardinality drift). Compaction: `params=["in_tree_stub", "llmlingua"]` (`test_compaction_contract.py:210`). The test IDs (`M-T-MEM-PROMO-01...`) trace to a test-strategy document that is gitignored.

**The `no_waiver` marker.** 23 tests carry `@pytest.mark.no_waiver`; a separate test pins the count and CI runs it as its own step (`contract-tests.yml`, step "Verify ratified no_waiver marker pin (14/9/23)"). It stops someone silently deleting an invariant, but it measures that the marker count is stable, not that the invariants are good.

## 5. Why it was built this way (decision table)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| `typing.Protocol` for ports | ABC base classes | Structural typing: an adapter needs no import of a base class and stays independent (`memory.py` docstring) | Conformance only checked by `isinstance` self-check and tests, not at class definition |
| Frozen, `extra="forbid"` Pydantic DTOs | Dicts, vendor objects | Vendor fields cannot leak through the seam (`common.py:110-122`) | Adapters carry mapping code; more lines |
| Two adapters per port where it matters (Mem0 + Letta; LLMLingua + stub) | One adapter per port | The second adapter is what *proves* the seam | Double maintenance; proof is against fakes |
| Contract tests parametrized over adapters | Per-adapter tests | Same assertions for both: a swap cannot change behaviour silently | Tests written to the least common behaviour |
| AST tests for layering | import-linter contracts | Can check things import graphs cannot (a function signature has no default; no `hashlib` outside `webhook.py`) | Hand-written per rule; `dial.py` hole |
| Composition root with no defaults | Fallback adapters when missing | A missing auth dependency fails loudly (`composition.py` docstring; gate C) | Verbose wiring |
| Own port over LiteLLM | Call LiteLLM directly | Provider-blind promise | The review says it "adds little" |
| 24 uv workspace members | One package | Enforces dependency direction per package (`pyproject.toml:10-34`) | "Heavy for a solo pre-user project" |

## 6. Theory behind it (the "lecture" part)

### 6.1 Hexagonal architecture (ports and adapters)
Proposed by Alistair Cockburn (2005). The application core defines **ports**: interfaces for what it needs from the world (driven ports, e.g. "store a memory") and what the world can ask of it (driving ports, e.g. "execute a request"). **Adapters** translate between a port and a concrete technology. The hexagon shape is only a drawing: it says there are many sides, not a top and a bottom. Close relatives: Clean Architecture (Martin) and Onion Architecture (Palermo). All three share one rule: source-code dependencies point inward toward the domain.

*In my project:* `ports/` is the inside; `adapters/` and the channels are outside; `kernel/` uses ports only.

### 6.2 The dependency rule and dependency inversion
Dependency Inversion Principle (the D in SOLID): high-level policy must not depend on low-level detail; both depend on an abstraction owned by the high-level side. Formally, for modules A→B meaning "A imports B", the allowed graph is a DAG in which every edge from `adapters` goes to `ports`, never the reverse. A violation is any edge `kernel → adapters` (except the composition root, whose job is to know both).

Enforcement options, from weak to strong: convention; code review; import-graph linter (import-linter "forbidden" and "layers" contracts); AST or type-level tests; separate packages so the import fails at build time.

*In my project:* separate workspace packages, plus AST tests for `kernel/auth` and `gateway/policy.py`; import-linter is installed but has one unrelated contract.

### 6.3 Structural versus nominal typing
In nominal typing an implementation must declare "I implement X" (inheritance). In structural typing it conforms if it has the right methods and signatures. Python's `Protocol` is structural for static checkers; `@runtime_checkable` lets `isinstance` check only that the *method names exist*, not their signatures or return types. So `isinstance(self, MemoryPort)` is a smoke check, and mypy plus contract tests do the real work.

*In my project:* `on_init` raises if the adapter is not a `MemoryPort`; the contract suite checks behaviour.

### 6.4 Contract tests (adapter conformance)
A contract test is a test suite written against the *interface*, then run against every implementation. It is the Liskov Substitution Principle made executable: any adapter must be usable wherever the port is expected. A good suite tests invariants (idempotency, error classes, ordering), not just happy paths. Two kinds exist here: **parametric** (same test, each adapter) and **parity** (both adapters in one test, results compared).

What it does not prove: behaviour of the real vendor. If the test double is wrong, both adapters can pass and production still fails. The remedy is a smaller set of *integration* tests against the real service, run less often (the project has smoke scripts under `scripts/live/`, not in CI).

*In my project:* the memory and compaction swaps rest on fakes.

### 6.5 Anti-corruption layer and DTO discipline
From Domain-Driven Design (Evans): an anti-corruption layer translates a foreign model into your own so the foreign vocabulary never spreads. The adapter plus a strict DTO is one. The strictness (`extra="forbid"`, primitives-only metadata) is the point: leniency is how vendor types leak.

*In my project:* `MemoryEntry.metadata` accepts only `str | int | float | bool` (`memory.py` DTO docstring).

### 6.6 Composition root
One place near the program entry point where concrete classes are chosen and injected. Everything else receives dependencies by constructor or argument ("pure DI", no container). Benefit: tests pass fakes with no patching; cost: the root grows.

*In my project:* `build_gateway` takes all eleven dependencies keyword-only (`composition.py`).

### 6.7 When a port is premature
A port earns its cost when there is (a) a second real implementation, (b) a need to test without the vendor, or (c) a vendor risk the business cares about. With one adapter, a port is a guess about the seam; it may be in the wrong place. Rule of three: wait for the second case, then abstract.

*In my project:* LLM, cost, state and serialization each have one adapter, so those four seams are untested guesses.

## 8. Glossary

| Term | One-line definition |
|---|---|
| Port | An interface the core owns for something it needs or offers; here a `Protocol` plus DTOs |
| Adapter | Code that implements a port on top of one concrete vendor or channel |
| Driving / driven port | The world calls the core (gateway) / the core calls the world (memory, LLM) |
| Dependency rule | Source dependencies point inward, toward ports and domain |
| Composition root | The single place that picks concrete adapters and wires them |
| `typing.Protocol` | Structural interface: conformance by shape, not inheritance |
| `@runtime_checkable` | Lets `isinstance` test a Protocol; checks method names only |
| DTO | Data transfer object; here frozen Pydantic models with `extra="forbid"` |
| Contract test | Suite written to the port, run against every adapter |
| Parity test | One test using two adapters, asserting they agree |
| import-linter | Tool that checks import-graph contracts; configured here for one rule only |
| AST gate | Test that parses source with `ast` and asserts a structural rule |
| `no_waiver` marker | pytest marker for invariants that may not be skipped; count pinned (23) |
| uv workspace | Several Python packages under one lockfile |
| Anti-corruption layer | Translation boundary protecting your model from a foreign one |
