## 2. The problem (business view, plain English)

In 2026 most engineers write code with an assistant. They are testing something specific: **can you read, judge and fix code on your own?** An engineer who reviews AI-generated code must spot a wrong complexity, a mutable default, a swallowed exception, a float used for money, a merge that duplicates rows. That skill comes from having written such code by hand. For an AI Solutions Engineer role at a Swiss bank or insurer the Python bar is practical, not exotic: data wrangling, small services, tests, correctness with money and dates, and clear explanation.

Finance analogy: Excel and mental arithmetic. A banker uses a spreadsheet for everything, yet is expected to sanity-check a number in their head ("that interest can't be 40%"). The assistant is the spreadsheet; this chapter is the mental arithmetic.

## 4. How it works (the practice system)

A 30-minute session, every day, four weeks:

```
 0-3 min   read the task; restate it in one sentence; write 2 examples + 1 edge case as asserts
 3-8 min   say the brute force and its complexity; name the data structure that improves it
 8-23 min  code in a bare editor (no assistant, no autocomplete, docs allowed: help, python.org)
23-28 min  run asserts; add tests for empty input, one element, duplicates, negatives, None
28-30 min  write the complexity line; compare with the model solution; log the bug type
```
Timer on. Stop at 30 minutes even if unfinished; unfinished is a data point.

## 6. Theory (the lecture)

### 6.1 Data structures and complexity
Big-O notation describes growth of cost with input size n. Common classes: O(1) < O(log n) < O(n) < O(n log n) < O(n^2). **Amortised** O(1) means the average over a sequence of operations (a list `append` occasionally resizes).

| Structure | Operation | Cost (CPython) |
|---|---|---|
| `list` | index `a[i]`, `append`, `pop` | O(1) (append amortised) |
| `list` | `x in a`, `a.index(x)`, `remove`, `insert(0, x)`, `pop(0)` | O(n) |
| `list` | `sort` / `sorted` | O(n log n) (Timsort, stable) |
| `dict` | get, set, delete, `in` | O(1) average, O(n) worst case |
| `set` | add, remove, `in` | O(1) average |
| `set` | union / intersection | O(len(a) + len(b)) / O(min) |
| `collections.deque` | `append`, `appendleft`, `pop`, `popleft` | O(1) |
| `collections.deque` | index in the middle | O(n) |
| `heapq` (min-heap on a list) | `heappush`, `heappop` | O(log n) |
| `heapq` | `heapify` | O(n) |
| `heapq.nsmallest(k, ...)` | | about O(n log k) |
| `bisect` on a sorted list | `bisect_left/right` | O(log n) search, `insort` O(n) |
| `str` | concatenation in a loop | O(n^2) total; use `"".join(parts)` |

Space complexity counts extra memory. Choosing the structure is the main lever: a dict from value to index turns two-sum from O(n^2) to O(n). Master theorem-style recursion analysis is rarely asked; know that binary search is O(log n), merge sort O(n log n), DFS/BFS O(V + E).

### 6.2 Comprehensions and generators
A **list comprehension** `[f(x) for x in xs if p(x)]` builds a list; `{k: v for ...}` a dict; `{x for ...}` a set. In Python 3 the loop variable does not leak. A **generator expression** `(f(x) for x in xs)` is lazy: it produces items on demand and holds O(1) memory. A **generator function** uses `yield`; calling it returns an iterator; state is kept between yields. Use `yield from` to delegate. Generators are **single-pass**; to reuse, recreate or materialise with `list`. Rules of thumb: need a list or length → list comprehension; just iterating or feeding `sum`, `any`, `all`, `max` → generator expression; huge or infinite stream → generator function. Useful `itertools`: `islice`, `chain`, `accumulate`, `groupby` (needs input sorted by the key), `product`, `combinations`, `zip_longest`; `zip(strict=True)` since 3.10.

Readability: a nested comprehension with two `for` clauses and a condition is the limit; beyond that use a loop.

*In my project:* Not in the sources: whether my collector scripts stream log files lazily (`3.6-the-scripts.md`). Do not claim generator use there.

### 6.3 Dicts, sets and `collections`
Keys must be **hashable** (immutable: str, int, tuple of hashables; not list or dict). `dict` keeps insertion order (guaranteed since 3.7). Methods: `get(k, default)`, `setdefault`, `pop(k, default)`, `update`, merge `a | b` (3.9+), `.items`. **Set algebra**: `a | b` union, `a & b` intersection, `a - b` difference, `a ^ b` symmetric difference; sets are unordered. From `collections`: `Counter` (multiset; `most_common(k)`, arithmetic), `defaultdict(factory)` (missing key creates a default), `deque(maxlen=k)` (sliding window, O(1) both ends), `namedtuple`. `functools.lru_cache` memoises pure functions. Sorting: `sorted(xs, key=..., reverse=...)`; stable; `operator.itemgetter` for key functions. `heapq` gives a min-heap; for max-heap negate keys.

*In my project:* none to cite specifically; the pattern appears in the ledger reconciliation exercise, the same completeness idea as my parity checks (`1.3-parity-safety-net.md`: compare populations, report missing, extra and different).

### 6.4 Typing
Annotations are **hints** stored on functions; Python does not enforce them at runtime. Static checkers (mypy, pyright) read them. Modern syntax (3.10+): `list[int]`, `dict[str, int]`, `int | None`. Tools: `Optional`, `Union`, `Callable[[A], B]`, `TypeVar` and generics (3.12 added `def f[T](x: T) -> T`; check current), `TypedDict`, `Literal`, `Final`, `Protocol` (structural interface: any class with the right methods conforms), `Iterable`/`Iterator`/`Mapping` for parameters (accept the widest type, return the narrowest). `from __future__ import annotations` delays evaluation. Typing documents intent and catches mismatches; it does not validate data at runtime. For runtime validation use Pydantic (validates and converts) or explicit checks.

*In my project:* ports are `Protocol` classes with frozen Pydantic DTOs (`2.1-ports-and-adapters.md`).

### 6.5 Dataclasses
`@dataclass` generates `__init__`, `__repr__`, `__eq__` from annotated fields. Options: `frozen=True` (immutable, hashable with `eq=True`), `order=True` (comparison by field order), `slots=True` (less memory, no `__dict__`), `kw_only=True`. Mutable defaults need `field(default_factory=list)` (a bare `[]` raises `ValueError`, protecting you from the shared-default bug). `__post_init__` runs after `__init__` for validation; for a frozen class set derived fields with `object.__setattr__`. `dataclasses.replace(obj, x=...)` makes a modified copy; `asdict` converts to dict. Compare: `NamedTuple` (immutable tuple, unpacking), `TypedDict` (typing only, a plain dict at runtime), Pydantic model (runtime validation, serialisation, more overhead). Prefer dataclasses for internal value objects and Pydantic at system boundaries.

*In my project:* frozen, `extra="forbid"` Pydantic DTOs at the port boundary (`2.1-ports-and-adapters.md`).

### 6.6 Exceptions
Hierarchy: `BaseException` → `Exception` → (`ValueError`, `KeyError`, `OSError`, …); `KeyboardInterrupt` and `SystemExit` derive from `BaseException`. Statement: `try / except X as e / else / finally`; `else` runs when no exception; `finally` always runs. Re-raise with `raise` (keeps traceback) and chain with `raise New(...) from e`. Define custom exceptions by subclassing `Exception`; build a small hierarchy so callers catch by category (for example a retryable `TransientError`). **EAFP** ("easier to ask forgiveness than permission": try, catch `KeyError`) vs **LBYL** (check first); EAFP avoids races. Do not use `assert` for input validation (stripped with `-O`). Python 3.11 added `ExceptionGroup` and `except*` for concurrent errors. Catch broadly only at boundaries (a request handler, a job runner), and log with `logger.exception`. Fail closed when correctness matters: an unexpected state should stop or escalate, not continue silently.

*In my project:* a typed error hierarchy at the ports (`2.1-ports-and-adapters.md`) and "all errors fail closed to `escalate`" in the deliberation loop (`2.4-deliberation-loop-and-receipts.md` 9b).

### 6.7 Context managers
A context manager guarantees setup and teardown around a block: `with open(path) as f:`. Protocol: `__enter__` returns the resource; `__exit__(exc_type, exc, tb)` runs on leaving; returning a true value suppresses the exception. `contextlib.contextmanager` turns a generator into one: code before `yield` is setup, after is teardown; wrap the `yield` in `try/finally` (or `except`/`else`) so teardown runs on error. Also `ExitStack` (dynamic number of contexts), `suppress`, `redirect_stdout`. Uses: files, locks, database transactions (commit on success, rollback on exception), temporary directories, timers, patching in tests, acquiring and releasing a rate-limit slot.

### 6.8 Testing with pytest
Tests are functions named `test_*` in files `test_*.py`; plain `assert` (pytest rewrites assertions to show values). Core features: **fixtures** (`@pytest.fixture`, scope function/module/session, `yield` for teardown, shared in `conftest.py`); **parametrize** (`@pytest.mark.parametrize("x, expected", [...])`); `pytest.raises(ValueError, match="...")`; `pytest.approx` for floats; built-ins `tmp_path`, `monkeypatch`, `capsys`; markers (`skip`, `xfail`, custom). **Mocking** with `unittest.mock`: patch the name where it is *used*, not where it is defined; prefer dependency injection (pass the clock, the sleeper, the HTTP client) so no patching is needed. Style: arrange-act-assert; one behaviour per test; deterministic (seed random, inject time); test edge cases and failure paths. Test pyramid: many unit tests, fewer integration, very few end to end. **Coverage is not correctness**, and a green run means little if tests are not collected or only check shape.

*In my project:* the false-green story (tests not tracked, CI scoped to a sub-folder), and that fakes and scripted models prove shape, not behaviour (`2.6-testing-and-ci-honesty.md`); fixture-based `make ci` (`4.6-ci-that-can-fail.md`).

### 6.9 pandas basics
Core types: `Series` (labelled 1-D) and `DataFrame` (labelled 2-D). **Index alignment**: operations align on labels, not positions. Selection: `df.loc[rows, cols]` by label or boolean mask, `df.iloc[...]` by position; `df[(df.a > 0) & (df.b == "x")]` (parentheses required); `df.query("a > 0")`. Create columns without loops: `df["chf"] = df["amount"] * df["rate"]` or `df.assign(...)`. **Group-by**: `df.groupby("k").agg(total=("amount", "sum"), n=("amount", "size"))` (named aggregation); `transform` returns same-length output (for example share of group total); `groupby(...).head(k)` after sorting for top-k per group; `nlargest`. **Join**: `pd.merge(left, right, on=..., how="left", validate="many_to_one", indicator=True)`; `pd.merge_asof` joins each row to the latest earlier row (both sides sorted, same dtype); `pd.concat` stacks. **Reshape**: `pivot_table`, `melt`. **Time**: `pd.to_datetime`, `.dt.to_period("M")`, `df.resample("MS", on="date")`, `rolling`, `shift`, `pct_change`. **Missing data**: `isna`, `fillna`, `dropna`; `groupby` drops NaN keys by default (`dropna=False` to keep). **Dtypes**: `category` for repeated strings, nullable `Int64`, `datetime64[ns]`; watch object columns. **Performance**: vectorise; avoid `apply(axis=1)` and `iterrows` on big frames; read only needed columns; chunking. **Money**: floats are fine for analytics but not for ledgers; keep integer cents or `Decimal` in the system of record. Copy-on-write semantics have changed across recent versions (check current).

Banking details to know: `zoneinfo.ZoneInfo("Europe/Zurich")` for time zones, naive vs aware datetimes, business-day calendars, Swiss number formats with an apostrophe thousands separator (parse them explicitly, exercise 14), CSV delimiters.

*In my project:* the MSc thesis work used pandas and statsmodels in a notebook (`9.1-electricity-price-forecasting-setup.md`); which cells I wrote by hand is not in the sources I read.

### 6.10 Frequently asked extras
- **Decorators**: a function taking a function and returning a function; `functools.wraps` keeps the name and docstring; parametrised decorators are a decorator factory (exercise 12).
- **`*args` / `**kwargs`**: collect extra positional / keyword arguments; unpack when calling.
- **GIL**: in standard CPython one thread runs Python bytecode at a time, so CPU-bound threads do not run in parallel; use `multiprocessing` or native extensions; threads/`asyncio` help I/O-bound work. A free-threaded build exists from 3.13 (check current).
- **`__slots__`**, `@property`, `@staticmethod` vs `@classmethod`, dunder methods (`__repr__`, `__eq__`, `__hash__`, `__iter__`), iterators (`__iter__`/`__next__`), `with` and `__enter__`.
- **`logging`** not `print`; `argparse`; `pathlib.Path`; `json`; `csv`; `datetime`; `re` (compile once; greedy vs lazy).
- **Packaging/tooling (2026)**: virtual environments, `pyproject.toml`, a fast resolver/installer such as uv or pip, formatter/linter such as Ruff, type checker mypy or pyright (check current). My projects use `uv` with a frozen lock in CI (`4.6-ci-that-can-fail.md`).

## 8. Glossary

| Term | One-line definition |
|---|---|
| Big-O | Upper bound on how cost grows with input size |
| Amortised | Average cost over a sequence of operations |
| Hashable | Has a stable hash; can be a dict key or set member |
| Comprehension | Compact expression that builds a list, dict or set |
| Generator | Function or expression that yields items lazily, once |
| Iterator | Object with `__next__`; consumed as you iterate |
| `defaultdict` | Dict that creates a default value for a missing key |
| `Counter` | Dict subclass counting hashable items |
| `deque` | Double-ended queue with O(1) operations at both ends |
| Type hint | Annotation read by checkers, not enforced at runtime |
| Protocol | Structural interface: conformance by shape |
| Dataclass | Class with generated `__init__`, `__repr__`, `__eq__` from fields |
| Frozen | Immutable instance; assignment raises an error |
| EAFP / LBYL | Try and catch / look before you leap |
| Context manager | Object with `__enter__`/`__exit__` used by `with` |
| Fixture | pytest setup/teardown function injected by name |
| Parametrize | Run one test function over many input sets |
| Mask | Boolean Series used to select rows |
| Vectorised | Operation applied to a whole array in compiled code |
| `merge_asof` | pandas join to the nearest earlier key |
| Banker's rounding | Round half to even (Python's `round`, Decimal default) |
