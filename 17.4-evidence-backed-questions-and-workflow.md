# Course 17 - Chapter 17.4: Evidence-backed questions and the fixed workflow

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** Talk to Your Data routes a closed question set through a fixed Agent Framework workflow and ordinary specialist functions. Evidence identity, observation chronology, source dependencies and explicit freshness determine supported facts, partial answers, refusal and clarification.

## 2. The problem (business view, plain English)

A forecast user needs to know whether recorded checks passed, why a candidate met a selection rule and what triggered a monitoring alert. A fluent answer can still mix different models, periods or versions. Asking a model to interpret a spreadsheet does not establish which facts it may use. This prototype makes the evidence eligible before constructing an answer.

I defined specifications, made key decisions and supervised AI-assisted implementation and review; I did not manually author every line. The demonstrated explanation workflow is local and synthetic, with real framework execution but mock transport. Historical Databricks execution belongs to an earlier identified wheel. Fabric adapters have local tests; actual current-package Fabric integration is unproven. Live LLM and Teams implementation remain deferred.

## 4. How it works (technical walkthrough)

```text
explicit request
  -> RouteExecutor: refuse / clarify / choose exact supported topic
  -> PlanExecutor: evidence boundary -> ordinary specialist functions
  -> checked host plan: facts + operands + citations + qualifications
  -> TerminalExecutor: deterministic result or optional checked wording
  -> one public answer, with gaps retained
```

The project source paths below are relative code references, not instructions to run them.

1. `src/forecast/orchestrator.py:40` defines an explicit request: question, evidence, target, mode and supplied UTC `as_of`; current mode also needs a freshness policy. No automatic lookup means "latest" cannot silently change the subject.
2. `_route` at `:121` checks nonempty text, then prohibited operations, topic validity and exact normalized intent. "Which checks failed? Deploy it" is refused before reading evidence. "Explain it" clarifies even if a topic was supplied. This is a closed question interface, not text-to-SQL.
3. `src/forecast/evidence.py:628` validates structure, target identity, contradictions, chronology and eligibility. Packet-wide failures expose no factual payload; topic-specific missing evidence may permit other topics.
4. `src/forecast/specialists.py:316` dispatches ordinary Python functions. They do not converse, select tools, call models or invent missing operands. They produce typed assertions rather than completed answers.
5. `src/forecast/explanations.py:408` independently checks assertion coverage, calculations, source closure and qualifications before building the host plan. The framework sequences work; it does not certify truth.
6. `src/forecast/orchestrator.py:207` controls the optional callback and final release. A fresh workflow is created per public request; a request-local latch is set before awaiting a callback. It is not durable deduplication across restarts.

The retained July 2026 fixture uses baseline WAPE 0.40 and candidate 0.36. It is distinct from historical Databricks validation values near 0.324 and 0.298. A fixture labelled "observed" remains observed within the synthetic fixture, not a live business observation. The portfolio chatbot's retrieval path is separate and does not inherit this workflow's B-v1 guarantee.

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives considered | Why this one | Cost / risk |
| --- | --- | --- | --- |
| Exact intent table | Model router; broad classifier | Auditable bounded behavior | Paraphrases clarify; limited usability |
| Fixed acyclic workflow | Autonomous tool selection | Authority stays in code | Framework adds orchestration overhead |
| Explicit target and clock | Implicit latest/current state | Reproducible eligibility | Caller must supply correct context |
| Complete declared model set | Rank whatever scores arrive | Prevent hidden contenders | Upstream completeness still needs assurance |
| Topic-local gaps | Whole-request failure; guessing | Useful supported partial answer | Status aggregation is more complex |
| Observed operands only | Infer checks from successful stages | Preserve evidence strength | More evidence collection required |

These are choices for a trusted, bounded offline prototype. External evidence ingestion remains blocked pending resource limits; accepting decoded fixtures is not an internet-facing ingestion design.

## 6. Theory behind it (the lecture part)

### 6.1 Separate control flow from decision authority

A workflow defines which operations run and in what order. An authority boundary defines who may establish facts, choose actions and release results. Those are different properties: a graph can be perfectly executed while calculating from the wrong model. A deterministic acyclic graph also need not be an autonomous agent system. In this project, framework executors coordinate route, plan and terminal stages; ordinary functions own domain calculations.

### 6.2 Evidence as a typed relation

A scalar such as `0.36` is incomplete evidence. Its meaning includes subject, metric, unit, split, period, observation time and artifact identity. Think of a relational key: joining on metric name alone can associate one model's score with another model's version. Typed contracts also reject `true` where a count is required, despite Python treating booleans as integer-like values. In this project, identity and domain checks prevent superficially plausible but mismatched operands.

### 6.3 Chronology versus freshness

Chronology asks whether an observation was possible; freshness asks whether it is recent enough for the question. For a weekly outcome ending at Monday L, this contract requires observation at or after L plus seven days, and no later than `as_of`. Freshness is `age = as_of - observed_at`; stale means age exceeds the caller's limit, so equality is fresh. Republishing a report does not reset observation time. Historical mode ignores age, not impossible chronology. In this project, both the current policy and July fixture clock are explicit.

### 6.4 Source closure and dependency graphs

A derived claim needs all its operands and every operand's source. If `alert = worst_block > factor * validation`, a valid worst-block source cannot replace a missing validation source. Closure means recursively following a conclusion to its original eligible leaves. Shared leaves create correlated gaps: a stale validation source can block comparison and commentary together. In this project, required claim/source sets govern eligibility; one specialist's answer is never recycled as new evidence for another.

### 6.5 Completeness, contradictions and open-world reasoning

Absence is not falsehood. Missing check evidence means "unknown", whereas an observed false check supports a failure statement. Likewise, successful training may imply checks ran but cannot reconstruct eight independently observed check results. Duplicate equal semantic records are malformed; different values for the same semantic key are conflicting. Neither is repaired by last-write-wins. In this project, gaps suppress dependent facts and packet contradictions fail closed.

### 6.6 Ranking, target evaluation and selection bias

Ranking returns all minimum-error models within declared baseline and candidate sets. The target candidate's gate is a separate question: a losing candidate cannot borrow the winner's score. Requiring every declared validation score prevents an omitted contender from disappearing unnoticed, although a false upstream manifest remains an upstream risk. Test scores never fill missing validation scores. In this project, ties remain visible and no arbitrary tie-break appoints a champion.

### 6.7 Exact arithmetic and boundary semantics

Relative gain is `(baseline - candidate) / baseline`. With 0.40 and 0.36 it equals 0.10, or ten percent; this is four percentage points of WAPE, not ten points. The fixed promotion gate is `candidate <= 0.95 * best_baseline`; at 0.38 it passes by equality. Monitoring instead uses `worst_block > 1.25 * validation` OR either PSI above 0.20; equality does not alert. With validation 0.36, the block threshold is 0.45, and 0.46 triggers it. Decimal/fraction arithmetic avoids rounding a boundary before deciding. In this project, these examples are synthetic rule proofs, not causal business explanations.

### 6.8 Partial answers and monotonic evidence strength

Evidence status and presentation status are separate. One missing PSI claim can block commentary while complete comparison remains answerable. A provider failure can leave evidence eligible, allowing deterministic wording; it does not make evidence disappear. Conversely, beautiful wording cannot turn a gap into an answer. Deriving a rule result labels it inferred while retaining observed operands; derivation does not upgrade uncertainty. In this project, partial responses expose only eligible topic facts with their limitations.

## 8. Glossary

| Term | One-line definition |
| --- | --- |
| Intent | A supported question category, selected here by exact normalized text |
| Evidence eligibility | Whether supplied facts satisfy identity, time and dependency requirements |
| Semantic key | Identity plus subject, metric, split and period defining the same fact |
| Source closure | Every conclusion resolves to all required original evidence sources |
| Manifest | Explicit declaration of the model set that must be complete for comparison |
| Epistemic status | Whether a claim is observed, inferred or unverified |
| Freshness | Age of an observation relative to an explicit question time |
| Partial answer | Supported topics answered while unsupported topics retain gaps |
| Request-local latch | In-memory guard against a second callback within one workflow |
| Platform proof | Observation on the actual selected runtime, not a local adapter substitute |
