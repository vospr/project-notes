# Course 4 · Chapter 4.4: Leak-free evaluation: spatial blocks, validation vs test, "test once"

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** How evaluation was made leak-free: contiguous section blocks with a 10-section gap, validation separate from the benchmark's test volume, the promotion gate reading validation only, and test1 scored once per run.

## 2. The problem (business view, plain English)

The first redo pass trained on real labels and reported a good test number, but it also **chose the model and ran the promotion gate on that same test volume**. A number you used to make decisions is no longer an honest estimate of future performance. In addition, patches sampled at random from one volume overlap their neighbours, so a random train/validation split puts near-copies on both sides. This chapter is about making the reported number mean "how it does on data it never influenced".

Finance analogy: back-testing a trading rule. If you tune the rule on 2015-2020 and quote that period's return, you quote in-sample performance. If you test on 2021 and then tweak the rule until 2021 looks good, 2021 is in-sample too. And if you cut the sample at a random day, tomorrow's price is in training while today's is in test: you need an **embargo** (a gap) between the periods.

## 4. How it works

```
train volume: sections along axis 0 (401)                       separate volume
|0 ............ 290|291 ..... 300|301 ........... 400|         test1 (200 sections)
|   TRAIN (fit)    |  gap, unused |  VALIDATION       |         reported once per run
|  20,000 patches  |              |  5,000 patches    |         5,000 patches
                    decisions read only the VALIDATION column
```

**The split**: `n_val = round(n_sections * 0.25)`; train = `range(0, n − n_val − gap)`, validation = `range(n − n_val, n)`. For n = 401: n_val = 100, train = 0-290, gap = 291-300, validation = 301-400 (matches *README*; `test_block_split_is_contiguous_disjoint_with_gap`, *test_06:17-22*).

**Patch sampling**: each set draws random (section, row, column) positions only from its own section range, with its own seed offset (train seed, test1 seed+1, validation seed+2).

**One run in order**:
1. fit the Pipeline on train (:55)
2. score validation, compute the majority baseline on validation (:56-57)
3. re-score the current champion on **validation** (:58, :38-45)
4. gate decision from those three validation numbers (:59, comment "test1 is not read before this line")
5. **then** predict test1 once, compute test metrics, baseline and per-class report (:60-63)
6. log everything, including test1 numbers, register a model version (:65-80)
7. set the `champion` alias only if the gate promoted (:82-83)

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| Contiguous section blocks, not random patches | Random patch split; k-fold | Random splits put overlapping and adjacent patches on both sides | Single split, single seed; block choice arbitrary |
| 10-section gap | No gap; gap from autocorrelation | A cheap embargo | Unquantified |
| Validation from the train volume | Hold out part of test1 | Keeps test1 untouched by design | Validation lacks rare facies; accuracy optimistic |
| Gate and family choice on validation only | Gate on test1 (first pass) | Decisions must not use the reporting set | Gate blind to rare classes |
| Report test1 every run | Report only on request, once at the end | Informative, per-class report from the same single prediction | Test1 numbers pile up in MLflow; not once per project |
| Behavioural test (scrambled labels) | Code review only | Fails automatically if someone wires test1 into the decision | Cannot see feature-side leaks |
| Test names that spy on `Pipeline.predict` | Trust the README | Makes "once" executable | Counts by input length; fragile |

## 6. Theory behind it (the "lecture" part)

### 6.1 Three sets, three jobs
- **Training set:** fits parameters.
- **Validation set:** picks among models, hyperparameters, thresholds, and (here) decides promotion. Every decision uses information from it, so its error estimate is optimistically biased.
- **Test set:** estimates the generalisation error of the *final* chosen model. It is unbiased only if it influenced nothing. After you read it and change something, it has become a validation set.

The standard error of a test accuracy p̂ from n independent cases is √(p̂(1−p̂)/n). Differences smaller than about two of these are not evidence.

*In my project:* train sections 0-290, validation 301-400, test1; the gate reads validation, test1 is only reported.

### 6.2 A taxonomy of leakage
| Type | What leaks | Example | Guard |
|---|---|---|---|
| Target leakage | A feature derived from the label | "Account closed" used to predict churn | Feature audit |
| Preprocessing leakage | Statistics fitted on all rows | Scaler/PCA fit before the split | Pipeline, fit on train only |
| Duplicate / group leakage | Same entity in both sets | Same patient, same well, same trace | Group-aware split |
| Temporal leakage | Future in the past | Random split of a time series | Walk-forward split with embargo |
| Spatial leakage | Neighbours in both sets | Adjacent patches or sections | Spatial blocks with a buffer |
| Selection (adaptive) leakage | Test set used for choices | Pick a model by test score | Separate validation; one-shot test |

### 6.3 Spatial autocorrelation and blocked validation
Tobler's first law: near things are more related than distant ones. The **semivariogram** γ(h) = ½·E[(Z(x) − Z(x+h))²] grows with lag h until it levels off at the **range**; beyond the range points are roughly independent. If training and validation points are closer than the range, validation measures **interpolation** skill (filling in near known points), not **extrapolation** to new areas. Spatial cross-validation (Roberts et al. 2017) splits by blocks and inserts a **buffer** of about the range between train and test. A random split typically gives overoptimistic scores for spatial data. Even a perfect block split does not fix a **distribution shift** between regions; it only measures it honestly.

*In my project:* the gap is 10 sections with no estimate of the range; seismic layers are laterally continuous over kilometres (general property), so 10 sections may be well inside the range.

### 6.4 Selection bias and adaptive overfitting
If you evaluate k candidates on the same validation data and keep the best, the best score is biased upward: for k equally good models with independent noise σ, the expected maximum is roughly σ√(2 ln k) above the true level. Repeated, adaptive use of one holdout (look, change the model, look again) makes it worse, because later choices depend on earlier looks. Remedies: nested cross-validation, a fresh holdout when the old one is "used up", a **reusable holdout** (Dwork et al. 2015) or the **Ladder** mechanism (Blum and Hardt 2015) that reveals a new best score only when it beats the old by more than a step size.

*In my project:* the validation set is reused every time a challenger is gated against the champion (chapter 4.5); the champion's own score was selected on it. With few runs the effect is small; with many runs it grows.

### 6.5 Uncertainty with correlated samples
With m correlated samples per cluster and intra-cluster correlation ρ, the effective sample size is about n/(1 + (m−1)ρ). Illustration, with a ρ I did **not** measure: 5,000 validation patches over 100 sections is 50 per section; at ρ = 0.3, n_eff ≈ 5,000/(1 + 49·0.3) ≈ 320, and the standard error of an accuracy near 0.84 is about 2 points, not 0.5. Valid intervals come from a **cluster bootstrap** (resample whole sections) or from repeated blocked splits.

*In my project:* none of this is computed: "single seed, no confidence intervals".

### 6.6 "Test once" as a process
Test-set discipline is mostly about process, not maths: separate loaders so selection code cannot even import the test arrays; the test set evaluated at the end, by one command, once; a log of every look; and, when the set is used up, new data. The benchmark itself names the folder `test_once` and provides a second volume, test2.

*In my project:* the README documents the discipline; the code enforces only "not in the gate" and "one prediction per run".

## 8. Glossary

| Term | One-line definition |
|---|---|
| Validation set | Data used to make choices (model, threshold, promotion) |
| Test set | Data used once to estimate final performance; influences nothing |
| Spatial block | A contiguous region held out as a unit |
| Gap / buffer / embargo | Unused data between train and held-out blocks |
| Spatial autocorrelation | Nearby points are more alike than distant ones |
| Semivariogram, range | Half the mean squared difference by lag; the lag beyond which points are ~independent |
| Interpolation vs extrapolation skill | Accuracy near known points vs in new areas |
| Selection bias / winner's curse | The best of many noisy scores is too optimistic |
| Adaptive overfitting | Overfitting a holdout by repeatedly choosing based on it |
| Effective sample size | The number of independent samples that carry the same information |
| Cluster bootstrap | Resampling whole groups (sections) to get intervals |
| `test_once` | Folder name in the benchmark for held-out volumes meant for one evaluation |
| Behavioural test | Test that changes an input and asserts an output does not change |
