# Course 1 · Chapter 1.5: Feature ablation: can a hand-built feature be retired?

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

## 2. The problem (business view, plain English)

The model used a hand-built feature, the location-fit feature: a 0–4 score of how well the position's location policy fits the employee's location (0 = no match, 4 = same city). It was computed across 12+ dbt SQL files and was expensive to maintain. The team wanted to delete it, but only if the model would stay as good without it.

Finance analogy: you want to drop one factor from a credit-scoring model because collecting it is costly. Before you do, you prove two things: (1) how much the current model leans on it, and (2) whether a model rebuilt without it is just as accurate. The second question decides; the first only explains.

## 4. How it works (technical walkthrough)

Four methods, each answering a different question:

```
                    ┌─ Permutation (no retrain, ~4 min) ── does the CURRENT model use it?
 feature F ─────────┼─ Retrain without F (GPU, 3 variants) ── is quality the same WITHOUT it?  ◄─ decides
                    ├─ Segment analysis (forecast outputs) ── is any subgroup hurt?
                    └─ Integrated Gradients (before/after) ── where did the signal go?
```

**Step 1: permutation.** Load the trained the candidates-per-position model model. Shuffle F's column across rows, so its link to the label breaks but its distribution stays. Re-score the validation set and measure the metric drop. Repeat with 10 seeds. Also: **zeroing** (set F = 0 everywhere) and a **null control** (shuffle an unrelated feature, the employee-flag feature, 5 seeds) to measure the noise floor. 17 inference passes, 4 min on CUDA.

Result (the validation unbiased NDCG): permutation −0.00121 ± 0.00058; t(9) = −6.56, p = 0.0001; 95% CI [−0.0016, −0.0008]; Cohen's d = 2.07. Zeroing −0.00556. Null control −0.00073 ± 0.00015, p = 0.0004, so the "unrelated" feature was itself informative and the SNR (1.7×) is unreliable.

**Step 2: retrain.** Remove F from the numeric-columns list in the data-loading module (62 → 61 numeric columns), re-run ETL (the binary memmap files must be rebuilt), train 5 epochs to match the baseline. Compare 9 metrics. the candidates-per-position model: the validation NDCG +0.00011, the validation unbiased NDCG −0.00007, the validation proposal rate at 10 −0.10 pp, the test NDCG +0.00088, the test proposal rate at 10 +0.04 pp, assigns 90 → 90. the positions-per-employee model and OPP: trained on the experiment branch only, no baseline.

**Step 3: segments.** about 250,000 pairs common to both the candidates-per-position model forecasts. Score deltas around −1 point on a 0–100 scale overall; same-city & value 4: −2.32 (52k pairs); relocation needed: −4.96 (n = 203); value 1: +3.05. Per-position Spearman ρ between old and new orderings: median 0.909, mean 0.881, P5 0.684 across about 4,400 positions.

**Step 4: IG.** Mean |IG| per feature on both models; proxies gained +0.0063 against 0.0878 removed. The top-10 list barely moved.

**Decision.** All thresholds held → "proceed with deprecation".

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| Retrain as the decision metric | Permutation only | Permutation measures reliance of a model trained *with* F; only a retrain shows what a model *without* F can reach | GPU hours × 3 |
| Permutation as diagnostic | Skip it | Cheap (4 min); shows the current model does use F | Under-reports when F's values carry asymmetric meaning (zeroing was 4.6× larger) |
| 10 seeds + t-test + CI + Cohen's d | One shuffle | Separates a real effect from shuffle noise | Statistical significance ≠ practical size |
| Null control | None | Gives a noise floor for "how big is big" | Chose an informative feature; control failed |
| Thresholds and decision tree written before results | Decide after | Prevents moving the goalposts | Thresholds not tied to measured variance |
| Segment analysis mandatory | Overall metrics only | Averages can hide harm in a subgroup | Small segments (n = 203) are noisy |
| Only the candidates-per-position model baselined | All three | Time; the ticket's AC was met | Two of three variants have no comparison |

## 6. Theory behind it (the "lecture" part)

### 6.1 Permutation feature importance
For a trained model f, metric M and data (X, y): PI(j) = M(f, X, y) − M(f, X^(π_j), y), where X^(π_j) has column j randomly permuted. It needs no retraining. Repeat over K permutations and report mean ± sd.

What it measures: how much **this model** depends on feature j. Not whether j carries unique information. Two known biases:
- **Correlated features.** If j is correlated with k, permuting j creates unrealistic rows (j and k disagree), so the model is evaluated off-distribution. The effect can be over- or under-stated. Remedy: permute correlated features together (grouped permutation), or use conditional permutation.
- **Marginal preserved.** Permutation keeps the value distribution. Zeroing (or replacing with a constant) does not, and can show a much larger effect when one value has special meaning.

*In my project:* F is a composite of city match, preferred location, tier and timezone, so it is strongly correlated with its components. The review suggests permuting F together with its components. Zeroing was 4.6× permutation because 0 means "no correlation", a strong signal.

### 6.2 Drop-column (retrain) importance
DCI(j) = M(f_all) − M(f_{−j}), where f_{−j} is retrained without j. It answers "can the model do as well without j?" Correlated features can take over, so DCI is small for redundant features even if PI is large. Cost: one training run per feature per seed.

The catch is **training variance**: two training runs with different seeds differ by some σ_train. A single-seed DCI is one draw from a noisy difference. With n seeds per side, the standard error of the difference is about σ_train·√(2/n). You need that number before you can say a delta is "negligible".

*In my project:* single seed per side, deltas ±0.001. Consistent with "no effect", but no variance estimate. The review's fix: 3–5 seeds per side for all three heads, paired deltas against measured variance.

### 6.3 Null controls and the noise floor
A null control is a feature known to carry no information (best: a column of random noise you add on purpose). Permuting it shows the metric change from the procedure alone. Signal-to-noise = effect(j) / effect(null). Below about 2× you cannot tell them apart.

*In my project:* the control was the employee-flag feature, a real feature; it moved the metric (p = 0.0004), so it was not a null. SNR 1.7× is unreliable. Lesson: add a synthetic random column, never borrow a real one.

### 6.4 Statistical vs practical significance
With 10 seeds and low variance, a tiny effect becomes "highly significant". Cohen's d = mean / sd measures the effect relative to *shuffle* noise, not relative to what matters for the business. Always pair a p-value with an absolute effect size and a pre-set **practical threshold** (here 0.002 NDCG).

Related idea: **minimum detectable effect** (MDE). With your n and σ, the smallest effect you could detect at power 0.8 is about 2.8·σ/√n for a one-sample test. If the MDE is larger than your threshold, a "no effect" result proves nothing.

*In my project:* p = 0.0001 and d = 2.07, yet the effect is −0.0012, below the 0.002 threshold.

### 6.5 Ranking metrics used here
- **NDCG@k:** DCG = Σ (2^{rel_i} − 1) / log₂(i + 1) over the top k, divided by the DCG of the perfect order. 1 = perfect.
- **Unbiased NDCG:** NDCG reweighted to correct for position bias in the labels (items shown higher get more clicks or proposals).
- **Proposal rate@10:** share of positions where an actually proposed candidate is in the model's top 10.
- **Spearman ρ:** rank correlation between two orderings; 1 = same order.

*In my project:* the team's metrics; Spearman was my addition for ordering stability.

### 6.6 Integrated Gradients
For input x, baseline x′ and model F: IG_i(x) = (x_i − x′_i) · ∫₀¹ ∂F(x′ + α(x − x′))/∂x_i dα. Property (completeness): Σ_i IG_i = F(x) − F(x′). IG explains **one model's** prediction relative to a chosen baseline. Two limits matter here:
- It measures local sensitivity along a path, not counterfactual importance. A feature can have high IG and still be removable.
- Attributions from **two different models** are on different scales; completeness ties them to each model's own F(x) − F(x′). So "the proxies absorbed 7.1% of the removed attribution" is not a well-defined quantity.

### 6.7 Segment analysis and Simpson-type traps
An overall average can hide a subgroup that gets worse while a larger one improves. Check pre-defined high-risk segments, with sample sizes. Treat a large delta in a tiny segment as a hypothesis, not a finding.

*In my project:* relocation-needed (n = 203) at −4.96 is flagged as not robust; same-city & value 4 (52k) at −2.32 is the real, small cost.

## 8. Glossary

| Term | One-line definition |
|---|---|
| Ablation | Removing or disabling a component to measure its contribution |
| Permutation importance | Metric drop when one feature's column is shuffled, no retraining |
| Zeroing | Replacing a feature with 0 everywhere; changes its distribution |
| Drop-column importance | Metric difference between models trained with and without the feature |
| Reliance vs replaceability | Does this model use it / can a model do without it |
| Null control | A feature known to be uninformative, used to measure the noise floor |
| SNR | Effect of the feature divided by effect of the null control |
| Cohen's d | Mean effect divided by its standard deviation |
| MDE | Smallest effect a test can detect at a given power |
| NDCG | Ranking quality that rewards relevant items near the top |
| Proposal rate@10 | Share of positions where a really proposed candidate is in the top 10 |
| Spearman ρ | Correlation of two rankings |
| Integrated Gradients | Attribution method that integrates gradients from a baseline to the input |
| Completeness | IG attributions sum to F(x) − F(baseline) |
