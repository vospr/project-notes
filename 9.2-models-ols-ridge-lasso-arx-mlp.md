## 2. The problem (business view, plain English)

Given the 25 inputs of chapter 9.1, which model turns them into the best next-day price forecast? The thesis tries a ladder: plain linear regression (OLS), two regularised versions (Ridge, Lasso), a time-series model with autoregression (ARX), and a neural network, plain and tuned. Each model is a different bet on how complicated the price formation is.

Finance analogy: a ladder of pricing models for the same bond, from a flat-yield approximation up to a full term-structure model. The question is not which is fanciest but whether the extra complexity beats a simple model on data it has not seen, by more than the noise in the comparison.

## 4. How it works (technical walkthrough)

```
X (25 cols: const, 5 numeric std., 7 weekday, 12 month)   y = ln price
   ├─ OLS + HAC(24)               sm.OLS(...)                NB c8:3
   ├─ Ridge  α∈{.01…100} CV5      best α=100 (grid edge)     NB c9
   ├─ Lasso  α∈{.001…10} CV5      best α=0.001 (grid edge)   NB c11
   ├─ ARX = SARIMAX(1,0,0)+exog   AR(1) errors               NB c13:85
   ├─ MLP 128-64-32-1, BN+drop    loss=mse, Adam, early stop NB c15
   └─ MLP tuned (RandomSearch 5)  192 units, 1 hidden=32     NB c16-c18
 each: predict ln price → np.exp → MSE / MAPE / R² on price levels   NB c7
```

**OLS.** Fitted on the 18,294 training rows; HAC(24) standard errors. Test MSE 61.32, R² 0.725. Coefficients are in chapter 9.4 (rank-deficient design).

**Ridge and Lasso.** `GridSearchCV(cv=5, scoring='neg_mean_squared_error')`. Ridge: α = 100, MSE 60.62, R² 0.728. Lasso: α = 0.001, MSE 59.30, R² 0.734, with exact zeros for Wednesday, Thursday, Friday, May and November.

**ARX.** `SARIMAX(y_train, exog=X_train, order=(1,0,0))`. ar.L1 = 0.766, ln_Price_MAX 0.120, ln_Price_24 0.064, ln_Price_48 0.050, ln_Price_168 0.085. Prediction for the test period via `predict(start=test_df.index[0], …)`. MSE 83.80, R² 0.624, the worst model. Summary warns the covariance matrix is near-singular.

**Plain MLP.** Dense 128 → BatchNorm → Dropout 0.3 → Dense 64 → BatchNorm → Dropout 0.3 → Dense 32 → Dense 1, Adam, MSE loss, batch 32, up to 100 epochs, early stopping patience 10 and learning-rate halving on plateau. `validation_split=0.2` takes the *last* 20% of the training rows, so the validation set is chronological. Test MSE 64.38 (notebook) or 69.00 (thesis).

**Tuned MLP.** Search space: input units 32–256, dropout 0.1–0.5, 1–3 hidden layers of 32–128 units, learning rate 1e-4…1e-2 on a log scale; `RandomSearch`, 5 trials × 2 executions, 9 min 50 s. Best: 192 units, dropout 0.3, lr 0.00645, validation loss 0.0269. Retrained from scratch, test MSE 57.38 (notebook) or 60.60 (thesis).

**Evaluation.** All predictions are exponentiated and compared with exponentiated actuals; MSE, MAPE and R². The thesis calls the 30% block "validation" but it is the test set.

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| Log-price target, exponentiate for scoring | Model levels; asinh | Variance stabilising | Median-type forecast; scored on level MSE, fitted on log MSE |
| Regularised linear models next to OLS | OLS only | Literature: Lasso strong in EPF | Grids too narrow; no time-aware CV |
| ARX through SARIMAX | OLS with lags (already ARX) | Wanted a "classical time-series" model | Regression with AR errors; multi-step forecast; AR(1) hard-coded |
| Dense MLP | LSTM/GRU, gradient boosting | Simple; Lago et al. 2018 support MLPs | Papers cited for motivation use recurrent nets; boosting is the stronger tabular baseline |
| Keras Tuner random search | Grid; Bayesian | Cheap | 5 trials, no seed, log-space objective |
| Validation = last 20% of train | Random split | Keeps time order | Early stopping tuned on one stretch |
| No seeds, no repeats | Multi-seed average | Not done | Results cannot be regenerated; NN spread 5–7% |

## 6. Theory behind it (the "lecture" part)

### 6.1 Linear regression and OLS
Model y = Xβ + ε. OLS minimises Σ(y_i − x_i'β)² and gives β̂ = (X'X)⁻¹X'y when X has full column rank. With ln y as the target, a coefficient b on a 0/1 dummy means "about 100·b% higher price". Standard facts: unbiased under correct specification; Gauss-Markov optimal under homoskedastic uncorrelated errors; with many correlated regressors, estimates are noisy. If X does not have full rank, (X'X) cannot be inverted and software returns one of infinitely many solutions (chapter 9.4).

*In my project:* OLS on 25 columns gives the benchmark of the linear family, MSE 61.3.

### 6.2 Ridge and Lasso
Ridge: min ‖y − Xβ‖² + λ‖β‖₂², solution (X'X + λI)⁻¹X'y. It shrinks all coefficients and always has a unique solution. Lasso: min ½n⁻¹‖y − Xβ‖² + α‖β‖₁. The L1 penalty has corners on the axes, so the optimum often lands with some coefficients exactly zero (variable selection). Both trade a little bias for lower variance; both need **standardised** inputs, otherwise the penalty depends on units. λ is chosen by cross-validation, and for time series the folds should respect time (blocked or `TimeSeriesSplit`). Regularisation helps most when p is large relative to n; with 25 columns and 18,000 rows the gain is small. scikit-learn's Ridge uses a *summed* squared error, Lasso a *mean*, so the same number means different strengths. The Lasso-estimated autoregressive model with 24 hourly equations (LEAR) is a strong standard benchmark in this field (Uniejewski, Weron & Ziel 2018; Lago et al. 2021).

*In my project:* gains over OLS are 1.1% (Ridge) and 3.3% (Lasso), smaller than the NN's run-to-run spread; both best α values sit at a grid edge.

### 6.3 ARX versus regression with ARMA errors
Two different models are called "ARX".
(a) **Dynamic regression:** y_t = φ y_{t−1} + x_t'β + e_t. Lagged y is a regressor.
(b) **Regression with AR errors:** y_t = x_t'β + u_t, u_t = φ u_{t−1} + e_t. This is what statsmodels' SARIMAX fits when `exog` is given.
For (b), the one-step forecast uses the last observed residual, φ·û_{t−1}; h steps ahead the term is φ^h·û_T, which decays geometrically. Without new observations the forecast converges to x_t'β. AIC = 2k − 2ln L and BIC = k·ln n − 2ln L select the AR order (lower is better; BIC penalises more).

*In my project:* (b) with φ = 0.766, forecast 7,841 steps ahead without updates; effectively a regression whose lag coefficients were estimated under an error structure that the forecast cannot use.

### 6.4 The MLP and its training
A multi-layer perceptron maps x through layers h = ReLU(Wx + b), ending in a linear output; with enough units it approximates any continuous function on a compact set (universal approximation), but that says nothing about generalisation. Training minimises a loss by stochastic gradient descent; **Adam** adapts the step per parameter. **Dropout** randomly zeroes units in training (regulariser); **BatchNorm** normalises layer inputs per batch; **early stopping** halts when the validation loss stops improving and restores the best weights. Weights start random, so repeated runs differ unless seeds are fixed: for small tabular problems, run-to-run MSE variation of several percent is normal. On tabular data, tree ensembles (LightGBM) usually match or beat MLPs (Grinsztajn et al. 2022). Random search over hyperparameters beats grid search for the same budget when only a few hyperparameters matter (Bergstra & Bengio 2012), but five trials is not a search.

*In my project:* the tuned MLP has 15,713 parameters and one hidden layer; it moved test MSE between 57.4 and 60.6 across two runs.

### 6.5 Comparing models: noise first
A model "wins" only if its edge is larger than the noise of the comparison. Noise sources: random seeds, the single test window, serial correlation of errors. Use repeated runs for stochastic models and a paired test on the loss differences (Diebold-Mariano, chapter 9.3). Always add naive benchmarks (same hour yesterday, last week).

*In my project:* none of these were done; the ranking OLS < Ridge < Lasso ≈ tuned NN is a ranking of point estimates.

## 8. Glossary

| Term | One-line definition |
|---|---|
| OLS | Least-squares fit of a linear model |
| Ridge | Least squares with an L2 penalty on the coefficients |
| Lasso | Least squares with an L1 penalty; sets some coefficients exactly to zero |
| Regularisation | Penalty that trades bias for lower variance |
| LEAR | Lasso-estimated autoregressive model, a standard EPF benchmark |
| ARX | Autoregressive model with exogenous inputs |
| Regression with AR errors | y = Xβ + u with u an AR process; what SARIMAX+exog fits |
| AIC / BIC | Information criteria that penalise parameters (BIC more) |
| MLP | Feed-forward neural network of dense layers |
| ReLU | max(0, x) activation |
| Dropout | Randomly zeroing units during training |
| BatchNorm | Per-batch normalisation of layer inputs |
| Early stopping | Stop when validation loss stops improving |
| Random search | Sample hyperparameters at random |
| Keras Tuner | Library that runs hyperparameter searches for Keras models |
| Run-to-run variance | Difference between repeated trainings of the same stochastic model |
