# Course 2 · Chapter 2.3: LLM access and cost (LiteLLM, pricing, cost per call, stop reasons, truncation)

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** How model cost is computed and recorded: LiteLLM calls, a per-million-token price table, Decimal arithmetic, stop reasons and truncation flags. A recorded run of four calls cost about $0.03; the reviewer calls were about 80% of spend.

## 2. The problem (business view, plain English)

Regulated users need to know "what did this decision cost" per call, in a form an auditor can recompute. Two failure modes hurt: wrong prices (the number is confidently wrong), and invisible cut-offs (the model stopped mid-sentence and nobody knows).

Finance analogy: unit costing. Cost of a job = quantity x standard rate. The rate card must be correct and dated, and a job that was stopped half-way must be marked as such, or the cost report looks complete when the work was not.

## 4. How it works (technical walkthrough)

```
IterationController.run_deliberation      iteration_controller.py:548
   call(role, system, user) ──► ModelCaller   (LiteLLMModelCaller)
        picks model by role ──► LLMProxyPort.call(LLMRequest)   asyncio.to_thread
             LiteLLMAdapter.call  ──► litellm.completion("anthropic/<model>", max_tokens, ...)  (LL call)
             map finish_reason, strip cost fields, return tokens (no USD)
        ◄── ModelReply(content, in/out tokens, model, stop_reason)
   price(reply) ──► CostEvent ──► PiMonoNativeAdapter.record ──► Decimal USD or None
   CallRecord(tokens, cost, stop_reason, latency, prompt_sha256)  ──► Receipt
```

**LiteLLM.** One Python SDK that takes `"<provider>/<model>"` and calls Anthropic, OpenAI, Azure, and others through one signature, returning an OpenAI-shaped response (*LL* docstring; `litellm.completion(model=f"{request.provider}/{request.model}", ...)`). The version is pinned and its hash is checked by the supply-chain workflow (`.github/workflows/audit.yml`). The earlier plan, a Docker proxy "sidecar", was tried and dropped after a falsification test; LiteLLM is now used as a library only.

**The adapter's rules**: return tokens, never USD; strip any `cost_*`, `usd_*`, `price_*` field; map finish reason into `stop | length | content_filter | tool_use` and raise on anything else; cache identical `idempotency_key` calls in a process-local dict. The deliberation caller sets `idempotency_key = correlation_id = uuid4`, so the cache never hits (``).

**Credentials and routing.** The Anthropic key is read from the gitignored `.env` with `dotenv_values`, not exported to the environment, and the provider is fixed to `anthropic` with no `api_base`, so a call cannot reach the corporate gateway (`, 49-54`). The key reaches the adapter's `api_keys` map explicitly (``).

**Cost formula** (``): `cost = price_per_MTok / 1,000,000 x tokens`, separately for input and output, using `Decimal`, summed. Table (USD per million tokens, input / output): Haiku 4.5 1 / 5; Sonnet 5.5 2 / 10; Opus 4.7 5 / 25 (``). A pricing-table hash (`PRICING_TABLE_VERSION`) is stamped on each ledger entry (``), but the receipt's `CallRecord` does not carry it.

**Worked example** (receipt `23e61c4c`, call 2, reviewer counterargument on Sonnet 5.5): 452 in, 1,436 out. Input 452 x 2 / 1e6 = 0.000904. Output 1,436 x 10 / 1e6 = 0.01436. Sum = 0.015264. Matches the receipt. I recomputed all 12 calls in the three files; all match to the sixth decimal.

**Stop reasons and truncation.** A model call ends for a reason. `stop` = the model finished; `length` = it hit `max_tokens`. After the fix the controller copies each call's reason into `CallRecord.stop_reason` and lists `length` calls in `truncated_calls` (`iteration_controller.py:740`). Three states are kept apart on purpose: `[]` = none truncated, `[2]` = call 2 truncated, `null` = not recorded (schema /1). A default of `` had been wrong and was fixed in commit `cfcf496` (`receipt.py:100-102`). Tests: AC12, AC12b, AC12c.

**Unknown prices.** `make_price_fn` turns a `PricingTableMismatch` into `None`; the receipt then holds `cost_usd: null`, `cost_status: "unpriced"` and `total_cost_usd: null` if any call is unpriced (``; `iteration_controller.py:720-724`; AC9).

## 5. Why it was built this way (decision table)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| LiteLLM library as sole substrate | Own SDK wrappers per vendor; Docker proxy | One call signature, many vendors; sidecar failed a falsification test (*LL* header) | Library may lag provider features (*Review §8*, newer tech) |
| Port returns tokens, meter computes USD | Provider returns cost | One source of truth for money; adapters cannot leak vendor numbers (`llm_proxy.py:16-23`) | Meter must track every price; table rot |
| `Decimal` arithmetic | `float` | Exact decimal sums; no binary rounding in an audit number | Slightly more code; parity with a TypeScript original is formula-level only (``) |
| Unknown model gives `null` not 0 | Default to 0 or to a guess | A silent zero looks like "free" (AC9) | Total becomes `null` if any call is unpriced |
| Record `stop_reason` per call | Trust that outputs are complete | Run 1 showed a hidden cut-off | Flag only; no automatic response |
| 4,096 max tokens for every role | Per-role limits | Fixed the truncation seen at 1,024 | Weakens the implicit length bound on each role |
| Cheap model for producer and synthesizer, stronger one for reviewer | Same model for all | Cost: the two reviewer calls are about 80% of spend (run `23e61c4c`: $0.0251 of $0.0307) | Reviewer shares one vendor with producer; no vendor diversity |
| Key from `.env`, provider pinned | Environment variable | Keeps the key out of the process environment; no accidental routing to the gateway (``) | Local-only pattern |

## 6. Theory behind it (the "lecture" part)

### 6.1 Tokens, context and the cost of a call
A language model reads and writes **tokens** (sub-word pieces). An API call has a prompt of `n_in` tokens and a completion of `n_out` tokens, with a hard limit `max_tokens` on output and a **context window** on input plus output together. Providers bill per million tokens, with output typically several times dearer than input. Cost: `C = n_in * p_in / 10^6 + n_out * p_out / 10^6`. Extra terms exist: cached input at a discount, cache writes at a premium, batch discounts, priority tiers.

*In my project:* the formula is exactly the two-term version; cache and tier terms are deferred (`, 218`), so a run using prompt caching would be mispriced.

### 6.2 Why money must be exact (Decimal versus float)
Binary floating point cannot represent most decimal fractions (0.1 is a repeating binary fraction), so sums drift and equality tests fail. Money in an audit record should use decimal arithmetic or integer minor units. Python's `Decimal` gives exact decimal results at a chosen precision. Caveat: you must construct from strings or integers, not from floats, or the error comes in at the input.

*In my project:* prices are built from strings (`Decimal("2.50")`); costs are serialised as strings in the receipt (`receipt.py` via `mode="json"`).

### 6.3 Stop (finish) reasons and truncation
An LLM generation ends for one of a few reasons: natural end of turn, a stop sequence, the token limit, a tool call, a content or safety stop. OpenAI-style names: `stop`, `length`, `tool_calls`, `content_filter`. Native provider names differ (Anthropic: `end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `refusal`); a gateway such as LiteLLM normalises them. **Truncation** (`length`) means the output is incomplete: JSON may be invalid, an argument may stop mid-point. The standard guards are: check the stop reason on every call; treat `length` as a failure or retry with a larger limit; and size `max_tokens` from measured outputs.

*In my project:* run 1's reviewer text hit exactly 1,024 tokens; the fix records the reason but does not retry or fail.

### 6.4 Unit economics and the cost of multi-call patterns
A pattern with `k` sequential calls costs the sum of its calls, and latency adds up too (the calls here are strictly sequential: about 3 + 13 + 5 + 5 s). Where a model call repeats the same long context (question and evidence sent to producer, reviewer, critic, synthesizer), **prompt caching** can cut the input cost of repeated prefixes. Estimates must come from measured token counts per role, not from word counts: output length varies by 5x between runs of the same prompt (counterargument 1,024 vs 1,436 vs 1,493 tokens).

*In my project:* the reviewer's counterargument is the dearest single call (about half of spend) because it is the longest output on the dearer model.

### 6.5 Provider abstraction and its limits
A common SDK (LiteLLM) gives a lowest-common-denominator interface. Provider-specific features (structured outputs, citations, extended context management, prompt caching specifics) may not pass through, and parameter support differs by model (here, `temperature`). The abstraction therefore leaks at the edges; design for it by keeping the provider-neutral schema (the receipt) and adding provider-native paths inside the adapter.

*In my project:* the `temperature` rejection needed a model-specific exception list (``); the review warns that LiteLLM may not pass every Claude feature through.

### 6.6 Cost-measurement honesty: computed, metered, billed
Three different things: **computed** (tokens x list price in your code), **metered** (a proxy counts what passed through it), **billed** (the invoice). They should reconcile; differences come from caching, tiers, rounding, retries and failed calls. A claim should name which one it is.

*In my project:* the `$0.03` is computed. Failed calls are not in it: an early attempt cost `$0.001484` on the producer before the reviewer call was rejected, and that receipt was not committed.

## 8. Glossary

| Term | One-line definition |
|---|---|
| LiteLLM | Python SDK/proxy giving one call signature across LLM vendors |
| Token | Sub-word unit a model reads or writes; the billing unit |
| `max_tokens` | Hard cap on output tokens for one call |
| Stop / finish reason | Why generation ended: `stop`, `length`, ... |
| Truncation | Output cut at the token limit; incomplete |
| List price | Published per-token price, before discounts or caching |
| MTok | Million tokens |
| `Decimal` | Exact decimal number type used for money |
| Pricing table | Hard-coded map (provider, model) to input/output price |
| `PricingTableMismatch` | Error when a model has no row; mapped to `cost_usd: null` |
| `cost_status` | `priced` or `unpriced` on each call record |
| `truncated_calls` | Receipt field: sequence numbers of calls that stopped on `length`; `null` = not recorded |
| Virtual key | LiteLLM proxy credential with a budget (see 2.2) |
| Alias | A model name that the provider may re-point to a new snapshot |
| Prompt caching | Discounted re-reading of a repeated prompt prefix |
