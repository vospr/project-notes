# Course 3 · Chapter 3.6: The scripts: stdlib-only collectors, tests, and what I'd add (step attribution)

_Andrey Popov's project notes: how it works, why it was built this way, and the theory behind it._

**In short:** The tooling: standard-library-only Python collectors for Claude and Codex logs, pull-request APIs and step events, with sanitised outputs, hashed snapshots and 160+ tests. Specifies a nine-field step-event contract; step attribution is mostly unbuilt.

## 2. The problem (business view, plain English)

The programme's data lived in places nobody had joined: local session logs of two AI tools, pull-request systems on two code platforms, and a fixed monthly bill. Each source needed a small, auditable reader. The readers had to run on a locked-down client laptop with nothing to install, never leak transcript text or names, and give the same answer when run twice.

Finance analogy: month-end close tooling. Small scripts pull sub-ledger extracts, each stamped with the query, the period and a control total; a reviewer ties them to the general ledger by hand and signs. The scripts are the extract and the control, not the sign-off.

**Common design.** Standard library only (`argparse`, `json`, `glob`, `hashlib`, `datetime`, `unittest`). Output envelopes carry `schema_version`, a label ("token reconciliation—not currency"), the exact command, the collector's own SHA-256, the interval, a capture time and aggregate diagnostics, and never transcript text. Output is deterministic for fixed inputs, which is itself tested. Collectors fail closed on malformed input and count what they skip.

**Step attribution (the part I specified).** One record per lifecycle step with nine fields: `ticket`, `step`, `executor` (a set of agent, human, automation), `surface`, `outcome` (completed, bypassed, reverted for rework), `started_at`, `ended_at`, `evidence` (a stable reference, never a URL, path or free text), and `run_id` (the join key to cost). There is no person field by design. The local hook is inert unless an environment variable is set; `start` stores minimal state, `end` validates and appends atomically. The reconciler quarantines duplicates, missing run ids, unjoined rows, negative waits and missing human actions; it reports the execution mix with bypassed steps in a separate denominator, and handover wait as the minutes from an agent's verify step ending to the first human thread. Drill-down cells under a minimum size are suppressed.

**Dashboard.** A static, network-free page that reads only a contract-validated JSON file with no fields for transcript text, paths, URLs or identities.

## 5. Why it was built this way (decisions and trade-offs)

| Decision | Alternatives | Why this one | Cost / risk |
|---|---|---|---|
| Standard library only | pandas, requests, a package set | Nothing to install on a client laptop; fewer dependencies to review; stable for months | More code written by hand; dense scripts; still needs `az` and `gh` |
| Aggregate-only, sanitised outputs | Row-level exports | Per-person and transcript data are restricted | Cannot drill into an individual case from the artifact |
| Parse local logs | Wait for native telemetry | No export existed; the client could not provide history | Reverse-engineered, undocumented formats; my two worst bugs |
| Read-only, strict, fail-closed collection | Best effort | A silent gap would bias the proxy (chapter 3.2) | Whole run aborts on one malformed record |
| Frozen snapshots with digests | Re-run on demand | Claude logs are pruned at about 30 days | Reproducible from aggregates only |
| Event contract first (nine fields), implementation by another team | Build a full pipeline myself | The platform owns the agents; the interface is the deliverable | Not built; depends on another stream |
| Executor as a set | Single value | 8 of 11 modelled steps are human-plus-agent by design | Mix is a three-way split, not one percentage |
| No person field | Add actor id | Privacy and no individual ranking | Cannot tell a slow reviewer from a slow queue |
| Quarantine counters instead of dropping | Drop bad rows | Missing evidence stays visible | More output to read |

## 6. Theory behind it (the "lecture" part)

### 6.1 Dependency minimisation
Each dependency adds supply-chain surface (who can change it), install friction, and version drift. A **standard-library-only** tool trades development speed for reviewability and longevity. Fit: short-lived, security-sensitive tools run on machines you do not control. Misfit: when a library removes a whole class of bugs (parsers, date handling, numerics).

### 6.2 What tests prove, and what they cannot
A test checks that code meets an **oracle**. Kinds in this suite:
- **Example-based unit tests** on synthetic inputs (hundreds of small fixtures).
- **Differential testing:** two independent implementations must agree (collector against audit script).
- **Golden/hash-pinned tests:** a stored artifact must keep its digest.
- **Determinism tests:** same input, same bytes.
- **Fail-closed tests:** malformed input must abort without partial output.

The **oracle problem**: the expected value comes from the same understanding as the code. If the understanding of the log format is wrong, tests written from it still pass. Tests give confidence about internal consistency and regressions; ground truth needs an external source (a vendor report, an invoice, a second human reading raw data). A coverage figure or a test count says nothing about this. **Mutation testing** (changing code to see if tests fail) is a way to check test strength; the sources show none.

*In my project:* 160+ tests, 41 on the two usage collectors, all passing in the September close check. They prove consistency, not truth about the vendor formats.

### 6.3 Data contracts and honest labelling
A **data contract** fixes field names, types and meaning, with a `schema_version`. Validate at the boundary: reject unknown fields, malformed values and illegal combinations rather than coercing them. A label such as "token reconciliation—not currency" carries meaning with the data so a downstream reader cannot mistake a count for money. **Quarantine** (dead-letter) handling keeps rejected records and counts them instead of discarding.

*In my project:* the envelope label, the step-event field list (unknown fields are rejected), and the quarantine counters in the reconciler.

### 6.4 Privacy by design for metrics
Techniques: **allowlists** (emit only named fields), **aggregation**, **small-cell suppression** (hide counts below a threshold, here 5), removing direct identifiers, avoiding **linkage** through timestamps (the PR report notes timestamps stay correlatable). Remove the person field entirely if the use case does not need it.

*In my project:* sanitized PR reports, no person field in the step record, suppression of small drill-down cells, and a dashboard contract with no free-text field.

### 6.5 Instrument at the source versus reconstruct afterwards
**Reconstruction** (inferring phases and owners from logs and PR metadata) is brittle: formats change, identities are ambiguous, and the join key may not exist. **Instrumentation at the source** emits a structured event when the thing happens: contract-first, idempotent (an event id so retries are safe), atomically written, with a join key (`run_id`) planned from the start. Native standards exist: OpenTelemetry defines traces, metrics and logs and can carry usage, cost and tool events.

*In my project:* reconstruction produced the cost numbers and the bugs; instrumentation (the nine-field event) is the better design and is mostly unbuilt.

### 6.6 Handover wait as a queueing quantity
Wait time between an upstream finish and a downstream start is **queueing delay**. By Little's law, work in progress equals throughput times time in system, so a long queue after the fast step stays long however fast the step becomes. Definition matters: the wait after an *agent* step (nobody has noticed it finished) is a different problem from the wait between two human steps (capacity). Measuring it needs the finish event and the start event; a recorded vote or comment is a proxy for the start.

*In my project:* the agent-finished-to-human-started wait is the quantity the programme's lead named as invisible; it is specified, not measured.

## 8. Glossary

| Term | One-line definition |
|---|---|
| Collector | A script that reads one source and writes a versioned, labelled aggregate |
| Envelope | The JSON wrapper with schema version, label, command, interval, diagnostics and rows |
| Frozen snapshot | A stored output with a SHA-256, kept because the source is pruned |
| Oracle (test) | The independent source of the expected value in a test |
| Differential testing | Running two implementations and requiring identical output |
| Fail-closed | On malformed input, abort rather than guess |
| Quarantine | Keeping rejected records, counted, outside the result |
| Step event | One record per lifecycle step with executor, surface, outcome, times, evidence, run id |
| Executor set | Any of agent, human, automation for one step |
| Handover wait | Minutes from an agent step finishing to the first human action |
| Small-cell suppression | Hiding counts below a minimum to protect privacy |
| Run id | Identifier of an agent run; the join key between step events and cost |
